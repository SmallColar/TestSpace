- 需登录后才能进入任一模块

## 3. 模块一：录制任务 Recording Task

### 3.1 Tab A · 新建（三步向导）

新建任务是一个**三步向导**，三个节点**在页面上平铺展示**，与后端三个阶段卡点一一对应：

```
① 录制信息  →  ② 编排规则  →  ③ 生成自动化用例
```

#### 节点 ① 录制信息

| 字段 | 说明 |
|---|---|
| 网址 | 目标页面 URL |
| 录制工具 | 下拉，**本期仅 `playwright`**，预留扩展位 |
| 录制黑名单 | 需过滤的请求（静态资源等） |

> 原「录制方式（AUTO_RECORD / MANUAL_RECORD）」**本期取消**。

交互：填写 → 点击【开始录制】→ 页面展示**录制过程**（实时进度）与**录制结果**
→ 用户**逐条确认哪些接口需要、哪些不需要**（勾选，见 §5）

#### 节点 ② 编排规则

两种生成方式：
1. **取用上一步的录制结果**，**拖拽接口**生成编排规则（交互见 §3.2）
2. **基于历史编排规则**更新，生成新的规则

> 此设计解除了旧版「新建任务需先选编排规则」与「规则由录制结果生成」之间的先后矛盾：规则改为在录制完成后现场生成。

#### 节点 ③ 生成自动化用例

展示用例生成的过程与结果，逐条确认后提交入库。

### 3.2 拖拽交互（节点 ②）

采用 **两栏式拖拽排序**（非画布）：

```
┌─────────────────┬──────────────────────┐
│  接口池          │  编排序列             │
│ （录制结果接口）  │ （拖拽排序，可增删）   │
│  ○ GET /users   │  1. POST /login      │
│  ○ POST /users  │  2. GET  /users      │
│  ○ GET /users/1 │  3. PUT  /users/1    │
└─────────────────┴──────────────────────┘
```

- 左栏 → 右栏拖拽 = 加入编排序列
- 右栏内上下拖动 = 调整调用顺序
- 右栏可移除条目、设置每条接口的参数

> **定稿**：采用两栏式拖拽排序。备选方案「画布连线」支持分支/并行，但对线性调用链过重，列为后续可升级项。

### 3.3 Tab B · 查看
- 展示**当前用户创建**的任务列表（管理员可看全部）
- 点击某条任务 → **任务详情** = 录制信息 + 录制结果

## 4. 模块二：编排规则库 Rule Library

> 现状：`ArrangeRule` 仅作为任务的从属产物存在，**没有独立的管理模块**。本期升级为独立资源。

### 4.1 Tab A · 新建

支持**三种来源**：

| 来源 | 说明 |
|---|---|
| **① 基于历史规则** | 选择一条已有规则 → **基于它新建副本**，或**更新原规则** |
| **② 从录制结果拖拽生成** | 根据录制得到的接口列表，**手动拖拽接口**组装出新的编排规则 |
| **③ 上传测试用例** | 上传测试用例文件，**提取其中的步骤**，反推出编排规则 |

### 4.2 Tab B · 查看
- 展示**全部**编排规则（共享可见）
- 点击某条规则 → **规则详情**

## 5. 确认机制（贯穿三个卡点）Confirmation

### 5.1 卡点保留
原有的三个阶段卡点**全部保留**（行为与顺序不变）：

| 卡点 | 阶段 | 产物 |
|---|---|---|
| 1 | `RECORD` 录制 | 业务接口列表 |
| 2 | `PARSE` 编排解析 | 编排规则 JSON |
| 3 | `GENERATE` 用例生成 | 用例列表 |

> 三个卡点与「录制任务」新建向导的三个节点（§3.1）**一一对应**：节点① 录制信息 → 卡点 1；节点② 编排规则 → 卡点 2；节点③ 生成自动化用例 → 卡点 3。

### 5.2 确认方式（本次变更）
**三个卡点统一改为**：

```
统一展示该阶段全部产物
   → 用户逐条查看、逐条勾选
   → 每 10 条为一批，一批一批确认并提交保存
   → 全部批次提交完毕，进入下一阶段
```

要点：
- 支持**勾选**（选中/取消选中）每一条
- **分页/分批**：每批 10 条
- **批量提交**：按批次提交保存，而非整阶段一次性提交
- `GENERATE` 卡点提交后，用例进入「自动化用例库」

## 6. 模块三：自动化用例库 Case Library

> 现状：`TestCase` 仅落库，前端只显示原始 JSON，**没有执行能力**。

模块下分两个 Tab：

| Tab | 内容 |
|---|---|
| **用例列表** | 用例展示 / 详情 / 运行（§6.1 ~ §6.5） |
| **环境管理** | 维护运行环境（§6.6） |

### 6.1 列表
- 展示所有自动化用例（共享可见）
- 每条用例可编辑（仅本人 / 管理员）

### 6.2 用例详情需展示
| 内容 | 说明 |
|---|---|
| **公共变量** | 该用例提取出的变量（见 §8） |
| **校验点** | 断言列表（对应 `assertions`） |
| 步骤 | 接口调用链 |

### 6.3 运行
- **选择环境**（见 §8.2）后运行
- 支持**单条运行**与**批量运行**
- 运行完成后可**查看运行结果**

### 6.4 运行结果展示
按**步骤**展开，无论成功失败都要能看到**中间步骤结果**：

```
步骤名 / 状态(成功|失败) / 耗时
   ├─ 请求（method、url、headers、body）
   ├─ 响应（status、body）
   └─ 校验点结果（每条断言：期望 vs 实际 / 通过与否）
```

### 6.5 本期实现范围：**假跑**
- 真实执行引擎**本期不实现**，先做**假跑（模拟执行）**
- 假跑规则：**随机产生成功/失败结果**
- 无论成功或失败，**都要展示中间步骤结果**（结构同 §6.4）

### 6.6 环境管理（Tab）

**归属**：位于「自动化用例库」模块下的独立 Tab。

**粒度**：**个人级** —— 每个用户维护自己的环境；**管理员可见全部**（查看/编辑）。

**字段**：

| 字段 | 说明 |
|---|---|
| 环境名称 | 如「测试环境」「预发环境」 |
| baseUrl | 该环境的根地址 |
| 环境变量（可选） | 环境中固定的变量（可扩展） |

**用途**：运行用例前选择环境 → 用例中的地址被替换为该环境的地址（见 §8.2）。

## 8. 贯穿机制 Cross-cutting

### 8.1 公共变量 Public Variables

**定义**：可以在多处复用、或通过修改变量值快速改变验证场景的内容。

**三类**：

| 类型 | 说明 | 例子 |
|---|---|---|
| **A · 关联提取** | 上一个接口的**出参**作为下一个接口的**入参** | `orderId`、`userId` |
| **B · 固定常量/凭证** | 基本固定、多处复用的内容 | 登录用户名、登录密码、数据库密码、token |
| **C · 参数化验证点** | 通过修改即可快速验证不同场景的输入 | 页面输入的数字、金额、页数 |

**机制**：

1. **在生成自动化用例时**识别候选变量
2. 系统**列出候选清单**，由**用户勾选确认**（半自动，方案 b）
3. 确认后，在该用例内**所有**该字段统一替换为占位符，形如 `{{orderId}}`
4. 运行到下游接口时，用占位符回填上游取得的真实值

> 现状：`extracted_variable` 表只完成了「提取」，**占位符替换与回填链路尚未实现**，本期补齐。

### 8.2 环境管理 Environment

**背景**：用户录制的可能是**正式线上环境**的网址，但希望在**自己的测试环境**上运行用例。

**要求**：
- 维护多套环境，每套含：**环境名称 + baseUrl**（+ 可扩展的环境级变量）
- 运行用例时选择环境 → 用例中的地址被替换为该环境的地址
- 环境管理入口与粒度见 §6.6（位于「自动化用例库」下的 Tab，**个人级**，管理员可见全部）
