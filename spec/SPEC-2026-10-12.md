## 1. 项目概述 Project Overview

**TestPilot** 是 Web 多 Agent 的 LLM ReAct Agent 系统，基于 Spring Boot 3 + Spring AI，通过 Spring AI MCP Client 对接独立进程运行的 Playwright MCP Server（可插拔扩展其它浏览器自动化方案）。

它将「浏览器操作」自动转化为「接口编排规则」→「标准化自动化测试用例」→「用户分步确认后幂等持久化」的完整闭环，并提供 Vue 3 前端页面与后端交互，降低接口自动化用例的编写成本。

核心价值链路：

```
浏览器录制 → 接口过滤 → 依赖分析/变量提取 → 编排规则解析 → 向量化入库
          → 用例生成(多入参) → 历史用例比对 → 分步人工确认 → 幂等写入
```

- 靶场验证地址：`https://app.reqres.in/`
- 目标形态：后端服务 + REST API + Vue 3 前端页面。

## 2. 目标与非目标 Goals & Non-Goals

> 本节用于**防止范围蔓延**，任何未列入 Goals 的功能默认视为 Non-Goals。

### 2.1 Goals（在范围内）

- **G1** 网页录制：支持 `MANUAL_RECORD` 与 `AUTO_RECORD` 两种模式，捕获 XHR/Fetch 接口。
- **G2** 编排规则：支持录入编排文本、上传手工用例文档两种来源，解析出结构化编排链路。
- **G3** 向量化：编排规则文本向量化入库，支持相似度检索复用（阈值可配）。
- **G4** 用例生成：同一编排规则 × 不同入参组合，生成多条独立自动化用例。
- **G5** 历史比对：语义比对历史用例库，判定「新建 / 需要更新 / 无需更新」。
- **G6** 分步人工确认：关键步骤（录制、编排解析、用例生成）产物展示给用户确认，确认后才推进/持久化。
- **G7** 浏览器自动化可插拔：默认 Playwright MCP，预留扩展口子支持 Selenium 等其它方案。
- **G8** 前端页面：Vue 3 + Vite，提供任务创建、阶段产物展示、分步确认的交互界面。
- **G9** 并发能力：支持 10+ 用户同时在线（异步 + 浏览器并发闸门）。

### 2.2 Non-Goals（明确不在范围内）

- **NG1** **不执行测试用例**：TestPilot 只生成并写入用例，不提供测试执行引擎、调度器或断言运行。
- **NG2** 不做多租户、SSO、细粒度权限/RBAC（单组织原型）。
- **NG3** 不做分布式浏览器农场/集群（单机原型，横向扩展属后续演进）。
- **NG4** 不做用例自愈、失败自动重跑、结果诊断。
- **NG5** 不做复杂自定义断言引擎/脚本式断言（仅内置基础断言：状态码、关键字段存在、响应时间）。
- **NG6** 不接入真实 CI/CD，不自动触发回归任务。

## 3. 用户角色 & 用户场景 User Roles & User Stories

### 3.1 角色

| 角色 | 说明 |
|---|---|
| R1 测试工程师（QA） | 主要使用者：通过前端创建任务、录制、录入规则、上传文档、生成用例并分步确认 |
| R2 平台管理员（Admin/DevOps） | 部署依赖（Docker）、维护浏览器 Provider/LLM 配置、关注资源占用 |

### 3.2 用户故事

- **US1** 作为 QA，我想在前端**手动/自动录制页面并捕获接口**，以便快速得到业务接口清单并即时查看。
- **US2** 作为 QA，我想**录入编排文本 / 上传手工用例文档**，以便系统解析出业务编排链路。
- **US3** 作为 QA，我想**分步查看并确认各阶段产物**（录制结果、编排链路、生成用例），以便在每一步把关、错了能及时修改或驳回。
- **US4** 作为 QA，我想**由同一编排多入参生成多条用例**，以便覆盖不同参数场景。
- **US5** 作为 QA，我想**看到历史用例比对结果**，以便避免重复建用例。
- **US6** 作为 Admin，我想**用 Docker 一键拉起依赖并切换浏览器 Provider**，以便快速部署与扩展。

## 4. 系统整体架构 System Architecture

### 4.1 分层视图

```
┌──────────── Frontend：Vue 3 + Vite（frontend/ 目录，独立构建）─────────────┐
└────────────────────────────── REST API（HTTP/JSON）────────────────────────┘
┌─ Controller 层 ── AgentTaskController / MockTestPlatformController ─────────┐
┌─ Service 层 ───── AgentTaskService(@Async) 分阶段流水线 + 确认点调度 ────────┐
┌─ Agent 层 ─────── 6 个 ChatClient Bean（Coordinator/Recorder/...） ─────────┐
┌─ Tool 层 ──────── 7 个 @Tool（ApiFilter/Dependency/Vector/...） ────────────┐
┌─ Browser 抽象 ─── BrowserAutomationProvider 接口 ── PlaywrightMcpProvider ──┐
┌─ 基础设施 ────── Spring AI MCP Client ── PostgreSQL + pgvector ── 异步池 ────┐
┌─ 外部进程 ────── Playwright MCP Server（独立 stdio 进程）───────────────────┐
┌─ 外部服务 ────── OpenAI 兼容 Chat + OpenAI Embedding ────────────────────────┐
```

### 4.2 设计原则（可扩展/复用）

- **面向接口编程**：浏览器自动化、模型调用、工具均以接口/抽象隔离，新增实现不改主流程。
- **复用优先**：基类实体（`@MappedSuperclass` 抽 id/时间戳）、统一返回 `R<T>`、全局异常处理、Prompt 模板集中常量。
- **策略/模板方法**：流水线用模板方法定义骨架，阶段间确认点用策略配置化控制。
- **约定优于配置**：配置项给默认值，改配置不改代码。

### 4.3 多 Agent 协作

6 个 Agent 均实现为 `ChatClient` Bean，各自绑定「系统提示词 + 专属工具集」：

| Agent | 职责 | 绑定工具 |
|---|---|---|
| CoordinatorAgent | 总调度、路由、协调子 Agent | 无（负责上下文编排） |
| RecorderAgent | 页面录制（两种模式） | BrowserAutomationProvider + ApiFilterTool + DependencyAnalyzeTool |
| RuleParseAgent | 解析编排规则 / 手工用例文档 → 编排 JSON | DependencyAnalyzeTool |
| VectorRetrievalAgent | 编排规则向量写入 / 相似度检索 | VectorStoreTool |
| CaseGenerateAgent | 多入参生成用例 + 历史比对 | TestCaseRenderTool + HistoryCaseSearchTool |
| ReviewAgent | 组装阶段确认产物（预览报告） | ReportPreviewTool |

- 所有系统提示词统一使用 Spring AI `PromptTemplate`，模板变量用 `{{xxx}}` 占位，支持动态渲染。
- `CoordinatorAgent` 负责决策/路由/上下文编排；`AgentTaskService`（`@Async`）负责确定性分阶段流水线执行。

### 4.4 浏览器自动化抽象（可插拔 Provider）

```
BrowserAutomationProvider（接口）
  ├── navigate(url) / click(sel) / fill(sel, val)
  ├── snapshot() / getNetworkRequests() / wait(...)
  └── close()
        │
        ├── PlaywrightMcpProvider   ← 默认实现，经 Spring AI MCP Client 调 Playwright MCP
        ├── SeleniumProvider        ← 预留扩展口子
        └── PuppeteerProvider       ← 预留扩展口子

BrowserProviderRegistry：按 testpilot.browser.provider 配置选择实现
```

- 每任务**独立 Provider 会话**，任务结束（含异常）在 `finally` 中 `close()` 释放浏览器资源。
- Playwright MCP 工具名映射：

| 需求命名 | Playwright MCP 工具名 |
|---|---|
| page.goto | browser_navigate |
| page.click | browser_click |
| page.fill | browser_fill |
| page.get_snapshot | browser_snapshot |
| page.get_network_requests | browser_network_requests |
| page.wait | browser_wait_for |

### 4.5 工具清单（7 个 `@Tool`）

| 工具 | 职责 |
|---|---|
| ApiFilterTool | 过滤原始网络请求，剔除静态资源/css/js/img/埋点 → 业务接口 |
| DependencyAnalyzeTool | 接口时序排序、识别上下游参数依赖、提取全局/局部变量、输出 JSONPath 变量表达式与编排顺序 |
| VectorStoreTool | 编排规则写入向量库、相似度检索 |
| HistoryCaseSearchTool | 查询历史用例库、语义比对、判定新建/需更新/无需更新 |
| TestCaseRenderTool | 按固定 JSON Schema 生成标准化用例，内置基础断言 |
| ReportPreviewTool | 组装阶段确认产物（预览报告），返回前端 |
| OpenApiPersistTool | **仅用户确认后**调用，幂等写入 Mock 测试平台 OpenAPI |

### 4.6 分阶段执行 + 确认点

```
POST /api/tasks → 落库(PENDING) → @Async 分阶段流水线：
  [RECORD] 录制 → 产物:业务接口列表 ──(确认点)── 暂停 WAIT_CONFIRM
       │ 用户 CONFIRM/REJECT/MODIFY
  [PARSE] 编排解析 → 产物:编排规则JSON ──(确认点)── 暂停 WAIT_CONFIRM
       │ 用户 CONFIRM/REJECT/MODIFY
  [GENERATE] 用例生成+历史比对 → 产物:用例列表 ──(确认点)── 暂停 WAIT_CONFIRM
       │ 用户 CONFIRM → OpenApiPersistTool 幂等写入 → COMPLETED
```

- 阶段枚举：`RECORD / PARSE / GENERATE / DONE`。
- 确认点可配置（`testpilot.confirm.checkpoints`，默认 `RECORD,PARSE,GENERATE`）；`GENERATE` 为**强制确认点**（未确认不写入）。
- 确认决策：`CONFIRM / REJECT / MODIFY`（确认 / 驳回 / 修改后确认）。

## 5. 功能需求 Functional Requirements（FR）

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-01 | 手动录制 | MANUAL_RECORD：用户自行点击，系统仅捕获 XHR/Fetch，Agent 不主动操作 |

| FR-08 | 文档解析 | 上传手工用例文档，解析测试步骤、绑定接口、提取编排链路 |
| FR-09 | 向量入库 | 解析后的编排规则文本向量化存入 pgvector |
| FR-10 | 相似度检索 | 支持相似度检索编排规则，阈值可配 |

| FR-14 | 确认后持久化 | 仅 GENERATE 阶段确认后，按用例唯一键幂等写入 Mock OpenAPI |

| FR-17 | 异步任务 | 前端提交后 @Async 执行，HTTP 不阻塞；可查询状态 |
| FR-18 | 资源释放 | 任务结束（含异常）释放浏览器 Provider 会话 |

## 8. API 契约 API Contract

统一返回结构：`{ "code": 0, "message": "ok", "data": { } }`

错误码约定：

| code | 含义 |
|---|---|
| 0 | 成功 |
| 40001 | 参数缺失/非法 |
| 40002 | 非法枚举值 |
| 40401 | 任务不存在 |
| 40901 | 状态不允许（重复确认等） |
| 50001 | 任务执行失败 |
| 50002 | 浏览器 Provider/MCP 连接失败 |
| 50003 | LLM 调用失败 |

### 8.1 POST /api/tasks —— 创建任务

请求：

```json
{
  "type": "RULE_TO_CASE",
  "mode": "AUTO_RECORD",
  "browserProvider": "playwright-mcp",
  "targetUrl": "https://app.reqres.in/",
  "config": {
    "blacklist": ["button.logout", "#delete-user"],
    "maxRounds": 20,
    "noNewApiThreshold": 3,
    "similarityThreshold": 0.8,
    "ruleText": "登录→查用户→更新用户 串联为一个用例",
    "manualDoc": "（可选，入口②时上传的文档内容）"
  }
}
```

响应：`{ "code": 0, "message": "ok", "data": { "taskId": 123 } }`

{
  "code": 0, "message": "ok",

  }

## 9. 模块详细设计 Module Design

### 9.1 config 包

- **McpClientConfig**：声明 Playwright MCP 的 stdio 连接（`npx @playwright/mcp@latest` + 参数），暴露 `ToolCallback[]` Bean；每任务据此创建独立 `McpSyncClient` 会话。
- **AgentConfig**：从 `AgentPromptConstant` 读取 6 个模板，构建 6 个 `PromptTemplate` 与 6 个 `ChatClient` Bean，注入各自工具集；配置 LLM 超时/重试；条件化装配 ChatModel/EmbeddingModel（无 key 不装配）。
- **AsyncConfig**：`@EnableAsync` + `ThreadPoolTaskExecutor`（core=10/max=30/queue=100），并构建浏览器并发 `Semaphore`（默认 6）。

### 9.2 prompt 包

- **AgentPromptConstant**：6 个 Agent 的系统提示词模板常量，`{{xxx}}` 占位；附 `{{xxx}}→{xxx}` 渲染桥接工具。

### 9.3 browser 包（可插拔扩展点）

- **BrowserAutomationProvider**（接口）：navigate / click / fill / snapshot / getNetworkRequests / wait / close。
- **PlaywrightMcpProvider**（默认）：经 Spring AI MCP Client 调用 Playwright MCP，按 4.4 工具名映射。
- **BrowserProviderRegistry**：按 `testpilot.browser.provider` 配置实例化并返回 Provider；新增实现只需注册，不改主流程。
- **BrowserProviderFactory**：每任务创建独立 Provider 实例，保证会话隔离。

### 9.4 tool 包（7 个 `@Tool`）

每个工具 = `@Component` + `@Tool` 注解方法，纯函数式、可测试：

- ApiFilterTool：原始请求列表 → 业务接口列表。
- DependencyAnalyzeTool：业务接口 → 时序 + 变量 + JSONPath + 编排顺序。
- VectorStoreTool：封装 PgVectorStore 的 save / similaritySearch。
- HistoryCaseSearchTool：检索历史用例 + 语义比对 → 三态判定。
- TestCaseRenderTool：编排 + 入参组合 → 标准 JSON Schema 用例（含基础断言）。
- ReportPreviewTool：阶段产物 → 预览报告 JSON。
- OpenApiPersistTool：**仅 GENERATE 阶段确认后**由服务层显式调用，幂等写入。

### 9.5 service 包

- **AgentTaskService**：`@Async run(taskId)` 分阶段执行器（模板方法骨架：record → parse → generate → persist）；每阶段产出物后按配置暂停（WAIT_CONFIRM）；`confirm(taskId, decision, payload)` 处理确认并推进下一阶段；`try/finally` 保证释放 Provider 会话；CONFIRM GENERATE 后触发 OpenApiPersistTool。

### 9.6 controller 包

- **AgentTaskController**：创建任务 / 查询状态（含阶段产物）/ 提交阶段确认。
- **MockTestPlatformController**：Mock OpenAPI 幂等写入。

### 9.7 frontend 包（frontend/ 目录，独立构建）

```
frontend/
├── package.json / vite.config.js（dev proxy → localhost:8080）
├── index.html
└── src/
    ├── main.js / App.vue
    ├── api/（axios 封装，对应第 8 章接口）
    ├── components/（TaskCreate、TaskProgress、ArtifactViewer、ConfirmPanel）
    └── views/（任务列表、任务详情/阶段确认）
```

### 9.8 common / dto 包

- `BaseEntity`（`@MappedSuperclass`）、统一返回 `R<T>`、`GlobalExceptionHandler`、请求/响应 DTO、枚举类。

## 10. 异常与边界场景 Error & Edge Cases

| 编号 | 场景 | 处理 |
|---|---|---|
| E-01 | MCP/浏览器 Provider 连接失败 | 任务置 FAILED，`finally` 释放资源，返回 50002 |
| E-02 | LLM 超时/限流 | 重试 3 次指数退避，仍失败 → FAILED（50003） |
| E-03 | 浏览器崩溃/页面加载失败 | 捕获异常 → FAILED，释放浏览器 |
| E-04 | 手动模式命中黑名单 | 仅记录告警，不拦截用户点击 |
| E-05 | 自动模式命中黑名单 | 跳过该元素，不执行点击 |
| E-06 | 连续无新增接口 | 达到阈值提前停止录制 |
| E-07 | 达到最大交互轮次 | 正常停止录制 |
| E-08 | 非 WAIT_CONFIRM 状态提交确认 | 返回 40901，不推进 |
| E-09 | REJECT 某阶段 | 任务置 REJECTED，停止后续阶段 |
| E-10 | MODIFY 后再次确认 | 以 modifiedPayload 为准覆盖产物并推进 |
| E-11 | 幂等写入重复 | 命中 unique_key 返回已存在，不重复创建 |
| E-12 | Embedding 维度不匹配 | 写入前校验维度，不匹配报错 |
| E-13 | pgvector 未就绪 | 任务 FAILED，提示先启动 Docker |
| E-14 | 空编排规则（无有效链路） | 任务 FAILED，提示无有效业务链路 |
| E-15 | 切换未注册的浏览器 Provider | 创建任务时报 40002，提示可用 Provider |

## 12. 验收标准 Acceptance Criteria（AC）

> 格式：Given / When / Then。

- **AC-01 创建任务**：Given 有效任务参数，When POST /api/tasks，Then 立即返回 taskId，任务 PENDING→RUNNING 异步推进。
- **AC-02 手动录制**：Given MANUAL_RECORD，When 用户点击页面，Then 捕获 XHR/Fetch；命中黑名单仅告警不拦截。
- **AC-03 自动录制**：Given AUTO_RECORD，When 系统探索，Then 黑名单元素不被点击；达阈值正常停止。
- **AC-04 分步确认**：Given 录制完成，When 任务进入 WAIT_CONFIRM，Then 前端展示业务接口产物，等待 CONFIRM/REJECT/MODIFY。
- **AC-05 编排解析确认**：Given 解析完成，When 确认点触发，Then 前端展示编排 JSON，确认后进入生成阶段。
- **AC-06 多入参生成**：Given 一套编排 + N 组入参，When 生成，Then 产出 N 条独立用例。
- **AC-07 历史比对**：Given 历史用例库，When 生成，Then 每条例用判定 NEW/UPDATE/NO_UPDATE。
- **AC-08 确认前不写入**：Given 用例已生成，When 任务 WAIT_CONFIRM，Then 未调用 OpenAPI 写入。
- **AC-09 确认后幂等写入**：Given GENERATE 阶段 CONFIRM，When 持久化，Then 写入成功；重复写入不产生重复用例。
- **AC-10 驳回/修改**：Given REJECT/MODIFY，When 确认，Then REJECT 终止、MODIFY 以修改后产物推进。
- **AC-11 浏览器可插拔**：Given 配置切换 provider，When 运行，Then 主流程不感知实现差异（默认 Playwright MCP 可用）。
- **AC-12 前端交互**：Given 前端页面，When 操作，Then 可创建任务、查看各阶段产物、分步确认。
- **AC-13 并发**：Given 10 个并发任务，When 执行，Then 浏览器并发被闸门限制、任务排队、无 OOM。

## 14. 风险与备选方案 Risks & Mitigations

| 编号 | 风险 | 影响 | 缓解/备选 |
|---|---|---|---|
| R-01 | Playwright MCP 工具名/版本变动 | 录制链路失效 | 锁 MCP 版本；Provider 层集中映射，一处改全局生效 |
| R-02 | Embedding 维度与模型不匹配 | 向量写入报错 | 维度配置化 + 启动/写入前校验 |
| R-03 | 浏览器内存爆炸 | 机器 OOM | 并发闸门限流 + headless 瘦身 + 任务排队 |
| R-04 | LLM key 缺失/限流 | AI 链路不可用 | 条件化装配 + 重试 + key 环境变量占位 |
| R-05 | 范围蔓延 | 工期失控 | 第 2 节 Non-Goals 明确边界，本文档为唯一基准 |
| R-06 | 10+ 并发单机承载不足 | 卡顿 | 闸门排队；未来演进浏览器农场（K8s/Selenium Grid） |
| R-07 | 手工文档解析不稳定 | 编排链路错误 | LLM 结构化输出 + JSON Schema 校验 + 分步确认兜底 |
| R-08 | 分步确认增加交互成本 | 用户嫌繁琐 | 确认点可配置，非关键阶段可自动通过 |
| R-09 | 多浏览器 Provider 适配不一致 | 行为差异 | Provider 接口统一契约，各自实现内部隔离 |
| R-10 | 前端构建链与后端耦合 | 部署复杂 | 前端独立 `frontend/` 目录，dev 用 proxy，生产 build 可进 static |
| R-11 | H2→PG、SimpleVectorStore→PgVectorStore 偏离原硬约束 | 需求分歧 | 已在变更记录登记，评审确认后锁定 |
