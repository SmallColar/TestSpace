## 1. 项目目标 Project Goal

TestPilot 为用户提供一条从真实 Web 页面流量到自动化 API 用例的核心链路：

```text
填写录制信息 → 浏览器操作并采集请求/响应 → 选择接口并拖拽成场景
             → 选择或复用历史编排规则 → LLM 生成完整用例
             → 结构校验 / 相似用例判断 → 用户确认 → 同步到自动化平台
```

用户提供的场景说明（例如“注册用户并查询详情”）和有序接口链路（A → B → C）共同构成生成上下文。模型根据各接口录制到的 URL、方法、请求头、入参、响应状态和响应体生成完整步骤、变量提取/传递和断言。

## 2. 首期范围与边界 Scope

### 2.1 首期目标 Goals

- G1 保留用户注册、登录、JWT 会话和管理员 `ADMIN` 角色逻辑。
- G2 新建任务以流程节点展现：录制信息 → 接口与场景编排 → 用例生成与确认。
- G3 录制任务能够保存请求和响应的可用信息；用户可查看、筛选并选择接口。
- G4 用户可将录制接口拖拽排序，构成一条或多条有序业务场景规则。
- G5 用户可手工选择历史编排规则，或请求模型给出相关规则推荐，再由用户确认采用。
- G6 LLM 依据被选中的规则及该规则引用的接口录制数据生成完整的结构化自动化用例。
- G7 生成结果经结构校验、接口引用校验、变量映射校验和相似度判定后，进入用户确认。
- G8 用户可查看规则库及模型生成的用例库，按权限查看、编辑自己的资源；管理员保留现有全量管理权限。
- G9 保留现有平台同步接入点；真实平台协议和字段映射须作为独立 Adapter 配置，不将模拟接口视为生产同步。

### 2.2 首期非目标 Non-Goals

- NG1 不做通用自主网页探索 Agent；录制阶段以用户操作指定网站、采集真实网络请求为主。
- NG2 不支持复杂分支、循环、并行流程；首期编排为有序线性链路。
- NG3 不做完整 API 测试执行引擎和 CI 调度；但需提供生成结果的静态可执行性检查。
- NG4 不移除用户、登录、注册、权限、admin 数据隔离逻辑。
- NG5 不在本轮讨论稿批准前删除既有功能或代码；后续以依赖审计和数据迁移方案决定移除项。

## 3. 角色与权限

保留 `SPEC-2026-10-15.md` 中的用户体系：注册用户默认为 `USER`；保留 `ADMIN` 管理员及现有登录鉴权。普通用户只能修改自己的规则、任务和用例；管理员继续遵循现有全量查看/管理规则。导航中的菜单不因角色隐藏，数据范围由后端授权校验。

## 4. 前端信息架构与交互

### 4.1 全局导航

采用左侧主导航，至少包含：

- **新建录制任务**：进入节点式新建流程。
- **录制任务**：查看任务状态和录制产物。
- **编排规则库**：查看、编辑和复用历史规则。
- **自动化用例库**：查看模型生成、人工修改及相似度处理后的用例。
- **个人中心**：保留现有用户资料/密码相关入口。

页面顶部保留当前用户、个人中心和退出登录。普通用户/admin 使用同一导航骨架。

### 4.2 新建任务节点

```text
① 录制信息  →  ② 选择接口并编排场景  →  ③ AI 生成用例并确认
```

节点状态需区分未开始、进行中、已完成和需处理。可返回前序节点修改输入；返回后应明确提示哪些后续产物将重新生成。

#### 节点 ① 录制信息

字段：任务名称、目标网站 URL、录制 Provider、探索目标与要求提示词。提示词同时描述希望 AI 探索的业务目标、边界，以及需要保留或排除的接口。开始录制后展示浏览器状态、采集数量和完成/失败信息。录制须捕获并保存：URL、method、query/path 参数、headers、请求体、响应状态、响应头、响应体及时间顺序。凭证等敏感字段需脱敏展示并避免写入日志。

#### 节点 ② 选择接口并编排场景

- 左侧接口池展示录制到的接口，支持查看请求/响应详情、筛选和排除噪音接口。
- 通过拖拽把接口加入右侧场景链路并调整顺序；允许移除和复制接口步骤。
- 一个任务可定义多个场景，每个场景具备名称、业务说明、接口序列和参数组合。
- 历史规则入口提供两种使用方式：模型推荐（展示推荐理由及匹配接口）和人工搜索/选择；应用规则前由用户确认接口映射。
- 历史规则引用的 API 与本次录制不完全一致时，禁止静默替换；展示差异并要求用户映射、跳过或取消。

#### 节点 ③ AI 生成用例并确认

- 可查看生成进度、调用模型状态、校验错误和相似用例候选。
- 逐条预览完整用例：步骤、请求定义、变量提取与传递、断言、清理步骤、生成依据。
- 用户可编辑、接受更新、另存为新用例、跳过重复项或删除草稿。
- 只有确认的用例才进入正式用例库并提交平台同步；同步状态与失败原因可追踪。

## 5. 数据结构与编排模型

编排规则必须显式引用接口，不以自由文本推断接口集合。建议核心结构如下（字段名称可在详细设计阶段调整）：

```json
{
  "scenarioName": "创建并查询用户",
  "description": "创建用户后使用响应中的 id 查询详情",
  "steps": [
    { "sequence": 1, "capturedApiId": 101 },
    {
      "sequence": 2,
      "capturedApiId": 102,
      "bindings": [
        {
          "source": { "step": 1, "jsonPath": "$.id" },
          "target": "path.userId"
        }
      ]
    }
  ],
  "parameterSets": [{}]
}
```

生成用例为可执行的中间表示（IR），最少包含：用例名称、场景/规则版本、请求步骤、步骤间变量映射、断言、测试数据、清理策略、生成模型及 prompt/schema 版本、相似用例决策和状态。每个请求步骤引用 CapturedApi 或其规范化快照，确保后续录制数据变化不会悄悄改变已有用例。

## 6. LLM 生成流程

### 6.1 输入上下文

每次生成只传入当前场景实际引用的接口数据，不把任务全部接口无差别塞给模型。上下文包含：

1. 场景名、业务描述、调用顺序和用户给出的限制；
2. 每一步的 method、URL 模板、headers、query/path 参数、body schema/样例；
3. 已捕获响应状态、响应结构/样例及可提取 JSONPath；
4. 参数组合、已确认变量绑定和历史规则（如有）；
5. 目标自动化平台支持的用例 Schema 与断言能力。

敏感值需在进入 LLM 前脱敏或转成变量引用。模型不得虚构录制数据中不存在的接口、参数或响应字段。

### 6.2 输出与验证

- LLM 生成完整用例 JSON，使用受约束输出/JSON Schema 校验。
- 校验每步接口引用、HTTP 方法、URL、必填参数、变量生产/消费顺序、JSONPath 和断言字段。
- 格式错误或引用错误可携带具体错误做有限次数修复；仍失败则将生成标为失败，保留错误详情供用户处理。
- 生成内容须保留输入来源，便于用户理解和审计。

## 7. 相似用例识别与生命周期

### 7.1 相似度检测原则

不能仅依赖用例名称或向量相似度。采用“硬匹配 + 语义候选 + 结构比对 + 人工决策”的多层判断：

1. **规范化指纹**：按场景内接口 method + 规范化 URL/操作标识 + 顺序 + 断言目标生成 fingerprint。忽略 query 参数值、动态 ID、时间戳和非业务 header 值。
2. **语义召回**：以场景说明、步骤意图和断言摘要检索历史用例，得到候选而非自动判重结论。
3. **结构相似度**：比较步骤序列相似度、接口重合度、变量绑定图、断言集合和参数语义；合成分数并保留分项解释。
4. **判定策略**：精确 fingerprint 命中作为强重复；高分候选提示“可能更新/重复”；中间区间交由用户选择；低分创建新用例。阈值需可配置并用真实项目样本校准，不在规格阶段写死未经验证的数值。

模型可辅助说明相似点和差异，但最终状态由规则和用户确认共同决定，不能让 LLM 单独删除或覆盖历史用例。

### 7.2 新增、更新、跳过、删除

| 情形 | 建议处理 |
|---|---|
| 没有相似历史用例 | 新增草稿；用户确认后成为正式用例 |
| 与历史用例高度相似且内容无实质差异 | 默认标记“重复候选”；用户可跳过，或明确另存副本 |
| 命中同一业务场景且步骤/断言有变化 | 展示字段级差异，用户选择更新原用例或创建新版本；默认不覆盖 |
| 仅参数集不同 | 优先作为同一用例的数据集/参数化场景；若平台模型不支持，再由用户选择拆分为多条 |
| 用户删除生成草稿 | 软删除并记录操作者、时间和原因；草稿未同步时不触碰平台对象 |
| 删除已同步用例 | 默认仅归档/停用本地记录；只有平台明确支持删除且用户再次确认时才调用删除接口 |

### 7.3 版本和幂等

- 用例有稳定业务标识、版本号和状态（草稿、待确认、已确认、同步中、已同步、同步失败、已归档）。
- 同一任务重试生成使用幂等键更新同一草稿，避免重复插入。
- 用户批准更新后创建新版本并保留旧版本快照和差异；平台更新成功后记录外部 ID/版本。
- 平台调用失败不得显示同步完成；提供单条重试，并保证重试幂等。

## 8. 导航资源管理

### 8.1 编排规则库

展示规则名称、业务说明、接口数、接口顺序摘要、来源、创建人、更新时间和版本。支持详情、复制、编辑、归档/删除、按场景语义检索。模型推荐应返回匹配原因和接口映射状态，用户确认后才应用。

### 8.2 自动化用例库

展示名称、关联场景、版本、相似度处理结果、生成状态、确认状态、平台同步状态、创建时间。详情展示接口步骤、输入输出映射、断言、参数数据、历史比对和版本差异。保留现有用户/admin 数据授权规则。

## 9. 后端设计建议

- 将 `AgentTaskService` 中录制、规则解析、上下文组装、LLM 生成、校验、相似比对和平台同步拆为单一职责服务。
- 建议边界：`RecordingService`、`ScenarioOrchestrationService`、`CaseGenerationService`、`CaseValidationService`、`CaseSimilarityService`、`TestPlatformAdapter`。
- LLM 提示词、输出 Schema 和模型配置版本化；模型调用记录耗时、token/用量（若可得）、错误类别和关联任务 ID，不记录明文敏感数据。
- 向量检索用于召回历史规则/用例候选；结构指纹与比较器负责确定性判定。
- 规则、录制接口、用例版本、平台同步记录应采用明确外键/版本引用，避免 JSON 文本成为唯一事实来源。

## 10. 现有功能清理原则

用户希望聚焦核心流程并清理无关实现。清理在实现阶段进行，先做引用与数据迁移审计，再逐项删除。登录注册、admin、鉴权、用户归属和权限逻辑必须保留。候选收敛对象包括与首期无关的假跑/运行页面、独立环境管理、上传规则来源、多余 Agent/工具和未使用 DTO；只有在确认没有前端、API、数据及测试依赖后再移除。旧 API 如暂时保留，应标记弃用并提供迁移窗口。

## 11. 验收标准 Acceptance Criteria

- AC1 未登录用户仍被引导至登录页；注册、登录、admin 登录和数据授权行为保持可用。
- AC2 用户可创建录制任务并查看实际采集的请求和响应样例，敏感信息按策略脱敏。
- AC3 用户可拖拽至少三个接口构成 A → B → C 场景，保存并回看顺序。
- AC4 可从规则库人工选择历史场景，也可查看模型推荐及理由；未经确认不得自动套用不匹配的接口。
- AC5 生成阶段输入仅包含场景选中的 API 及其录制请求/响应、规则、参数和已确认映射。
- AC6 LLM 输出完整用例步骤与变量传递，不止断言；无效接口引用/变量引用可被拦截并显示具体错误。
- AC7 相似候选展示相似分项和差异；系统不自动覆盖或删除正式历史用例。
- AC8 用户可确认新增、确认更新为新版本、跳过重复候选和删除未同步草稿。
- AC9 只有确认的用例进入平台同步；失败状态可见、可重试且重试不重复创建。
- AC10 导航可进入任务、规则库、用例库和个人中心；普通用户和 admin 保留既有权限范围。
